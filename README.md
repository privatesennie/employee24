# 🏛️ [프로젝트명] 공공기관 웹 접근성 개선 및 리뉴얼 프로젝트

## [고용24] 웹 접근성 강화 포트폴리오

## 1. 프로젝트 소개
* **설명:** 기존 공공 서비스의 딱딱한 인터페이스를 탈피하여, 현대적인 Glassmorphism(글래스모피즘) 디자인 트렌드를 반영한 [고용24] 모바일 웹 리뉴얼 프로젝트입니다. 특히 AI 챗봇 컨셉의 대화형 UI를 도입하여, 복잡한 '실업급여 수급 자격'을 사용자가 쉽고 직관적으로 자가진단할 수 있도록 프로세스를 개선했습니다.
* **진행 기간:** 2026.05.13 ~ 2026.05.15 (3일)
* **개발 인원:** 개인 프로젝트 (기여도 100%)

## 3. 사용 기술 스택 

### Frontend
* React.js & Vite : 컴포넌트 기반 개발로 복잡한 공공기관 UI의 유지보수성을 높이고, 빠른 응답 속도를 구현하기 위해 사용

### Design & Tools
* Figma : 웹 접근성 체크리스트를 기반으로 한 UI/UX 설계 및 프로토타이핑
* Lighthouse / Axe-core : 웹 접근성 진단 및 품질 지표 측정을 위한 도구 활용

### AI-Assisted Development (Vibe Coding)
* Google Gemini / Antigravity : 시맨틱 마크업 검토, ARIA 속성 최적화, 스크린 리더 호환 로직 리팩토링을 위한 페어 프로그래밍 도구로 활용
* AI 활용 목표 : 복잡한 공공기관의 정보 구조를 논리적인 접근성 표준에 맞춰 빠르게 재구성하고 오류를 사전에 방지

## 4. 사용자 작업 흐름 

**주요 과업: 챗봇 AI를 활용한 대화형 실업급여 수급 자격 자가진단 및 인증**
1. **메인 페이지 (진입점):** 직관적인 화면 구성과 하단 플로팅 챗봇 아이콘(FAB)의 툴팁을 통해 수급 자격 확인 페이지로의 자연스러운 접근 유도
2. **자가진단 진행 (Step 1~4):** 고용보험 가입 이력, 퇴사 사유 등 4단계의 체크리스트 진행 ('아니오' 등 부적격 항목 선택 시 즉각적인 가이드라인 및 관련 부서 연락처 노출)
3. **본인 인증 (Step 5):** 진단 완료 후, 개인정보(이름, 주민등록번호)를 입력하는 직관적이고 간단한 인증 절차 진행
4. **결과 분석 (로딩):** 애니메이션 스피너와 진행 상태 텍스트를 통해 정보 처리 중임을 사용자에게 시각적으로 안내
5. **최종 결과 안내 (Step 6):** 최종 수급 자격 진단 결과를 직관적인 아이콘, 강조된 텍스트와 함께 명확히 안내하여 사용자의 다음 행동 유도

## 5. AI 활용 및 개발 워크플로우 (Vibe Coding)
생성형 AI(Google Gemini / Antigravity)를 페어 프로그래밍 파트너로 적극 활용하여 개발 생산성을 극대화했습니다.

* **UI/UX 디자인 시스템 구현:** 프롬프트를 통해 Glassmorphism 스타일의 CSS 변수(그라데이션, 블러, 반투명 효과)와 애니메이션 뼈대를 빠르고 일관되게 생성
* **복잡한 상태 관리 로직 설계:** React의 `useState`를 활용한 다단계(Multi-step) 렌더링 로직 및 조건부 메시지 노출 로직을 AI와 함께 효율적으로 구현 및 최적화
* **동적 레이아웃 트러블슈팅:** 모바일 뷰포트에서 스크롤 시 발생하는 배경색 잘림 현상 등 까다로운 CSS 레이아웃 이슈를 AI 피드백을 통해 즉각적으로 진단하고 해결(`min-height` 적용 등)

---

## 6. 핵심 구현 기능
* **현대적 UI/UX (Glassmorphism):** 반투명 배경, 부드러운 그림자, 블러(`backdrop-filter`) 효과를 활용한 프리미엄 모바일 웹 디자인 적용
* **대화형 자가진단 프로세스:** 딱딱한 폼 대신 친근한 AI 챗봇 컨셉의 UI 구조와 부드러운 뷰 전환 애니메이션(`fadeInUp`) 적용
* **단계별 상태 관리 (Multi-step Form):** 단일 페이지 애플리케이션(SPA) 내에서 상태값에 따른 매끄러운 화면 전환(메인 -> 진단 4단계 -> 인증 -> 결과) 및 조건부 에러 메시지 렌더링
* **모바일 최적화 레이아웃:** 스마트폰 화면 비율(`max-width: 402px`)에 맞춘 유연한 Flexbox 레이아웃 및 커스텀 스크롤바 제어로 네이티브 앱과 같은 사용자 경험 제공

## 7. 디렉토리 구조
```text
src
├── assets             # 서비스 내 사용되는 각종 정적 이미지
├── App.css            # 전체 앱 레이아웃 및 디자인 속성 (Glassmorphism, KWCAG 호환 등)
├── App.jsx            # 메인 화면, 챗봇 검색 레이아웃 및 화면 상태 관리 (라우팅)
├── AuthForm.jsx       # 개인정보 간단 인증 화면 컴포넌트
├── Diagnosis.jsx      # 실업급여 수급 자격 자가진단 프로세스 컴포넌트
├── index.css          # 글로벌 폰트, 컬러 테마, 초기화 스타일 정의
├── main.jsx           # React 앱 진입점 (DOM 렌더링)
└── Result.jsx         # 자가진단 로딩 및 결과 확인 컴포넌트
```

## 8. 회고 및 인사이트

### [기술보다 중요한 배려, 웹 접근성]
단순히 시각적으로 화려한 웹사이트를 만드는 것보다, 어떤 사용자도 소외되지 않는 '기술적 배려'가 공공 서비스의 본질이자 프론트엔드 개발자의 중요한 역량임을 깨달았습니다.

### [AI와의 협업, Vibe Coding의 가능성]
AI 도구를 단순한 코드 자동 생성이 아닌, 표준 지침 준수 여부를 검증하는 '접근성 감리 파트너'로 활용했습니다. 이 과정에서 프롬프트를 통해 표준 가이드라인을 학습시키고 코드에 적용하는 능력이 실무 효율을 얼마나 높일 수 있는지 체감했습니다.
